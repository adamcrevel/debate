# debate

A structured, evidence-grounded multi-agent debate engine, driven by the
[`omp`](https://github.com) CLI. Two 3-agent teams — **FOR** and **AGAINST** —
argue a question through a fixed pipeline:

1. **Huddle** — each side's Researcher privately gathers evidence (with web
   search) and produces a brief for their team.
2. **Openings** — each side's Lead states their opening argument (FOR, then
   AGAINST), grounded in their team's brief.
3. **Rebuttal loop** — each side's Rebuttal agent responds in alternating
   turns (AGAINST first), bounded by `--max-rebuttal-rounds` and
   `--max-minutes`.
4. **Closings** — each side's Lead gives a closing statement (AGAINST, then
   FOR).
5. **Verdict** — a Judge agent (with web search) renders a verdict, unless
   disabled with `--no-judge`.

Every turn is persisted to a local SQLite database (`~/.debate/debate.db` by
default), so a debate's full transcript can always be replayed later with
`debate show`.

## Install

This project is managed with [`uv`](https://docs.astral.sh/uv/).

```sh
uv sync
```

This installs the `debate` console script into the project's virtual
environment. Run it with `uv run debate ...`, or activate the venv and run
`debate ...` directly.

## Usage

### `debate start` — create a new debate

```sh
uv run debate start --topic "Should cities ban private cars downtown?"
```

Flags:

- `--topic` (required): the debate's topic. Rejected with a clean error
  (nonzero exit, no debate created) if blank or whitespace-only.
- `--model` (default: unset): model name passed to `omp`'s `--model` flag.
  Left unset, `omp` falls back to its own configured default.
- `--max-rebuttal-rounds` (default: `2`): max rebuttal rounds, where one
  round is one turn from each side.
- `--max-minutes` (default: `10`): wall-clock budget, in minutes, for the
  rebuttal loop.
- `--no-judge`: disable the verdict stage for this debate (default: judge
  enabled).

These settings are stored on the debate row and become the defaults used by
every `debate ask`/`debate auto` call against it. Prints the new debate's id:

```
Created debate 1: Should cities ban private cars downtown?
```

### `debate ask` — run one question

```sh
uv run debate ask "What would it do to small businesses?"
```

Runs `<question text>` through the full pipeline on the **target debate**
(see "Active debate" below) and persists every turn. Accepts the same
`--model`/`--max-rebuttal-rounds`/`--max-minutes`/`--no-judge` flags as
`debate start`, plus `--debate-id`; any of them given here override the
target debate's stored defaults **for this one question only** — the debate
row itself is never modified. `--no-judge` can only force the verdict stage
off; it cannot turn a debate-level disabled judge back on.

### `debate auto` — run N questions with no human input

```sh
uv run debate auto --count 3
```

Runs `--count` consecutive questions on the target debate with no human
supplying any of them: each question is generated by the engine's Host
agent (informed by every question already asked in this debate, including
ones generated earlier in the same `auto` run, so it never repeats one),
then run through the same pipeline as `debate ask`. Accepts the same
`--debate-id`/`--model`/`--max-rebuttal-rounds`/`--max-minutes`/`--no-judge`
flags as `debate ask`, with identical override semantics. Prints each
generated question and its result as it completes.

### `debate show` — print a debate's transcript

```sh
uv run debate show 1
```

Prints the full persisted transcript for debate `1`: its topic, then each
question in the order it was asked, then every turn for that question in
the order the pipeline actually ran it (huddle, openings, rebuttal turns,
closings, verdict), labeled by stage/side/role, with a `[truncated]` marker
on any turn whose 200-word truncation backstop fired.

### `debate list` — list every debate

```sh
uv run debate list
```

Prints every persisted debate: id, topic, question count, and creation time.

## Active debate

Each `debate` invocation is a separate process — there is no interactive
session carrying state between commands. `debate start` prints the new
debate's id so a caller can remember it.

`debate ask` and `debate auto` both accept an optional `--debate-id`. When
it is **omitted**, they target the **most recently created debate**
(`Store.list_debates()`, ordered oldest-first — the last entry). When
scripting or driving this CLI from an LLM agent, pass `--debate-id`
explicitly once you know one; only rely on the "most recent" fallback
immediately after a `debate start` in the same script/session.

All five subcommands accept a global `--db-path` (before the subcommand
name) to point at a non-default SQLite file; it defaults to
`~/.debate/debate.db`.

## Out of scope

A Discord bot front-end is a deliberate future follow-up — intentionally not
part of this feature. This repo currently ships only the CLI (`debate`
command) and, separately, an `omp` skill wrapping it for LLM-driven callers.
